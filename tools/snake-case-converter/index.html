What snake_case Is and Why Python Uses It

snake_case writes multi-word identifiers in lowercase with an underscore between words: get_user_by_id, max_retry_count, created_at. It is the style PEP 8 recommends for Python, and it is the safe default for SQL column names. This generator converts any text into snake_case in one click, inside your browser.

The separator is the same in every case. What changes is the letter case, and the letter case signals whether the value is expected to change: lowercase means it can, uppercase means it should not.

A detail that bites people: identifier folding

PostgreSQL folds unquoted identifiers to lowercase. Create a column as UserName and it is stored as username; query it as UserName and it still resolves, because the unquoted reference folds too. The trouble starts when you quote it: SELECT "UserName" fails, because the stored name is lowercase. MySQL has its own variant of the same surprise on case-insensitive filesystems.

snake_case sidesteps all of it. If every identifier is already lowercase and underscore-separated, there is nothing to fold and nothing to quote.

How the conversion works

The converter splits on spaces, punctuation, existing hyphens and dots, and on a lowercase-to-uppercase transition inside a word. Every word is then lowercased and joined with a single underscore.

user name             → user_name
User Name             → user_name
userName              → user_name
user-name             → user_name
GetUserById()         → get_user_by_id
parse HTTP response   → parse_http_response
Max Retry Count       → MAX_RETRY_COUNT   (uppercase variant)

The acronym checkbox decides how a run of capitals such as HTTP is treated: with it on, the run stays intact and uppercase, with it off it is treated as an ordinary word. It only changes the output when the target style keeps capitals, so it affects camelCase and PascalCase; the underscore styles lowercase everything either way.

Frequently asked questions

What is snake_case?

snake_case writes multi-word identifiers in lowercase with underscores between words, as in get_user_by_id. PEP 8 recommends it for Python, and it is common in Ruby, Rust and SQL.

How is SCREAMING_SNAKE_CASE different?

Same separator, uppercase letters. It marks values that should not change: module constants, environment variables and enum members.

Why does PostgreSQL lowercase my column?

Because unquoted identifiers are folded to lowercase. snake_case is already lowercase, so nothing folds and nothing needs quoting.

Can it convert camelCase JSON keys?

Yes. Paste the camelCase key and pick snake_case. The split happens on the lowercase-to-uppercase transition, so getUserById becomes get_user_by_id.

Does this upload my text?

No. It is pure client-side JavaScript and nothing leaves your browser tab.

Is snake_case valid in JSON?

Yes. JSON keys are strings, so any convention works. snake_case is preferred by APIs aimed at Python and Ruby clients; camelCase dominates where JavaScript clients are the norm.
